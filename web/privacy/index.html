EVDial Privacy Policy

Last updated: 27 November 2026.

EVDial is an Android phone application developed in the public autonatoke-del/evdial project. This policy describes the Android client, including its optional F-Droid and Google Play distribution modes. The project's contact channel is EVDial support issues. The policy does not replace the separate policies of a carrier, SIP provider, browser or external service. Describing a distribution mode does not mean the application has been accepted into that store.

Contacts and call history

EVDial reads the Android contacts provider after contact access is granted. It uses names, numbers and contact photos for lookup and caller identification. Contact details are not uploaded to an EVDial server by these features. Android or another account provider may separately synchronize the device address book under its own settings.

The app reads the Android call log when it is the selected default phone application and call-log access is permitted, and uses it for recent calls and number lookup. SIP call history is stored separately in private app preferences, with up to 200 entries containing the remote number, call identifier, time, direction and duration. Speed-dial slots and preferences are also stored locally.

Adding or editing a contact opens an Android contact editor. Changing a contact's favorite status requires write access to contacts. Sharing a contact card or text sends the selected data to the application the user chooses. Copy actions put the selected value on the system clipboard.

Calls, SIP and messages

SIM calls and SMS are handled through Android and the user's mobile carrier. They are not routed through an EVDial-operated telephony service. Carrier billing and data-handling rules apply. EVDial can send an SMS after the user chooses to send it, selects EVDial as the default phone application and grants SMS permission. When EVDial is not the default phone application, it passes the draft and recipient to the user's SMS application for confirmation and delivery. It stores temporary local send-status information; it does not implement an SMS inbox.

SIP is optional and uses the server and account configured by the user. That server receives the information needed for registration and calls, including the SIP identity, destination and network connection information. Call audio is transmitted as part of the call. Once an account is saved, the app can register it when it starts; enabling incoming SIP support keeps a foreground service available for calls. EVDial disables Linphone push notifications and video capture/display in its application code.

The saved SIP password is encrypted with AES-GCM using a key held by Android Keystore. The username, server, transport setting, call history and other preferences do not have additional application-level encryption; they rely on Android's app storage protections. Protecting the saved password does not establish end-to-end encryption for calls. Network protection depends on the configured transport, provider and call negotiation.

Messaging shortcuts pass the chosen number, text or attachments to an installed messaging app, or open Android's share chooser. The receiving app and service control subsequent delivery and processing. EVDial does not have access to that app's conversations merely because a shortcut is present.

Recordings, files and photos

EVDial does not implement SIM call recording. Its recording feature plays an existing audio file selected by the user. The optional folder feature searches a user-selected local folder for filenames matching a call number and time. Android document permissions can be retained so the file or folder can be opened again. The app stores recording links locally and does not upload the recordings.

A user-selected wallpaper is copied and re-encoded in private app storage; the import does not preserve the source image's EXIF metadata. File attachments are selected through Android's document picker and passed to the chosen app only when the user invokes sharing.

Charging directory and external services

The bundled charging directory is an offline snapshot of selected Russian Open Charge Map records. Searching that bundled data is local and does not require device location access. See the dataset attribution.

Map and route buttons open external sites with the selected station coordinates or search text. Web search, charging websites, the project websites and DIAGNOST AI open in an installed browser's tab or browser window. These sites receive normal web requests and can apply their own cookies, accounts and privacy practices. Some linked services are proprietary.

Before the first DIAGNOST AI visit, EVDial explains that it is an external service and records the user's acknowledgement locally. The link does not automatically append contacts, the number in the dialer or call history. Information a user enters on the site is governed by that site's practices.

Updates and analytics

The website-distributed preview has a user-invoked updater. Checking for updates contacts https://autonatoke.ru/evdial/; downloading an update retrieves an APK from that site. The web server receives normal connection information, such as the IP address. EVDial does not implement background update polling or unattended installation.

When built with the F-Droid mode, the website updater is disabled, and the installer permission and update file provider are removed. The update action explains repository-managed updates and can open the installed F-Droid client or the F-Droid website. The selected repository and client have their own network behavior.

In Google Play builds, the website updater, installation permission and update file provider are also disabled. The update action opens the EVDial listing in Google Play or its website after the user taps. Updates are distributed by Google Play under its own policies.

No developer analytics, advertising SDK integration or crash-reporting service is implemented in EVDial's application source. This statement does not describe telemetry independently performed by Android, the mobile carrier, the SIP provider, a browser, or another installed app.

The manifest does not request location or camera access. Permissions can be changed in Android settings, and features that need revoked access may stop working. The manifest disables Android application backup. Clearing EVDial's storage or uninstalling it removes its private settings, SIP history, saved credentials and imported wallpaper. It does not delete contacts, the system call log, original recordings or data already sent to an external service.

Source and questions

Relevant implementation is in Phone.java, ContactsScreen.java, SipHistory.java, QuickSms.java, RecordingLink.java, WallpaperStore.java, EvLinks.java and AppUpdates.java.

Use the project issue tracker for questions about this document. Do not post phone numbers, SIP credentials, private contact cards, recordings or other sensitive data in public issues. For security reporting, see SECURITY.md.

Политика конфиденциальности EVDial

Обновлено: 27 ноября 2026 года.

EVDial — телефонное приложение для Android, разрабатываемое в открытом проекте autonatoke-del/evdial. Эта политика описывает клиент Android, включая отдельные режимы распространения через F-Droid и Google Play. Канал связи с проектом — обращения в поддержку EVDial. Политика не заменяет правила оператора связи, SIP-провайдера, браузера или внешнего сервиса. Описание режима распространения не означает, что приложение принято в соответствующий магазин.

Контакты и история звонков

После предоставления разрешения EVDial читает контакты из системного хранилища Android. Имена, номера и фотографии используются для поиска и определения звонящего. Эти функции не отправляют контактные данные на сервер EVDial. Android или другой поставщик учётной записи может отдельно синхронизировать адресную книгу в соответствии со своими настройками.

Приложение читает системный журнал вызовов, когда EVDial выбран приложением «Телефон» по умолчанию и доступ к журналу разрешён. Эти данные используются для недавних вызовов и поиска номера. История SIP-звонков хранится отдельно, в закрытых настройках приложения: до 200 записей с номером собеседника, идентификатором, временем, направлением и длительностью вызова. Номера быстрого набора и настройки также сохраняются локально.

Добавление и редактирование контакта открывает редактор контактов Android. Для изменения отметки «Избранное» требуется разрешение на запись контактов. При отправке карточки контакта или текста выбранные данные передаются приложению, которое указал пользователь. Команда копирования помещает выбранное значение в системный буфер обмена.

Звонки, SIP и сообщения

Звонки через SIM и SMS обрабатываются Android и мобильным оператором пользователя. Они не проходят через телефонный сервис, управляемый EVDial. Применяются тарифы и правила обработки данных оператора. EVDial может отправить SMS после того, как пользователь выберет отправку, назначит EVDial приложением «Телефон» по умолчанию и предоставит разрешение на SMS. Если EVDial не является приложением «Телефон» по умолчанию, черновик и получатель передаются SMS-приложению пользователя для подтверждения и отправки. EVDial временно сохраняет локальные сведения о состоянии отправки; входящие SMS приложение не обрабатывает.

SIP подключается по желанию пользователя и использует указанные им сервер и учётную запись. Сервер получает сведения, необходимые для регистрации и звонков, включая SIP-идентификатор, адрес вызываемого абонента и данные сетевого соединения. Во время звонка передаётся звук разговора. После сохранения учётной записи приложение может регистрировать её при запуске; включение входящих SIP-звонков поддерживает работу службы с постоянным уведомлением. В коде приложения EVDial отключены push-уведомления Linphone, захват и отображение видео.

Сохранённый SIP-пароль зашифрован алгоритмом AES-GCM с ключом из Android Keystore. Имя пользователя, сервер, выбранный транспорт, история звонков и остальные настройки не имеют дополнительного шифрования на уровне приложения: их защищают механизмы хранения данных Android. Защита сохранённого пароля не означает сквозного шифрования разговоров. Защита передачи по сети зависит от настроенного транспорта, провайдера и согласованных параметров звонка.

Кнопки мессенджеров передают выбранный номер, текст или вложения установленному приложению сообщений либо открывают системное окно выбора приложения. Дальнейшая доставка и обработка зависят от выбранного приложения и сервиса. Наличие такой кнопки не даёт EVDial доступ к переписке в этом приложении.

Записи разговоров, файлы и фотографии

EVDial не реализует запись звонков через SIM. Функция записей воспроизводит уже существующий аудиофайл, выбранный пользователем. Дополнительная функция папки ищет в выбранной локальной папке файлы, названия которых соответствуют номеру и времени звонка. Разрешение Android на доступ к документу может сохраняться, чтобы файл или папку можно было открыть повторно. Ссылки на записи хранятся локально; приложение не загружает сами записи на сервер.

Выбранное пользователем изображение для фона копируется и перекодируется в закрытое хранилище приложения. При импорте метаданные EXIF исходного изображения не сохраняются. Вложения выбираются через системное окно документов Android и передаются выбранному приложению только при вызове отправки пользователем.

Справочник зарядных станций и внешние сервисы

Встроенный справочник — офлайн-снимок выбранных российских записей Open Charge Map. Поиск по встроенным данным выполняется локально и не требует доступа к местоположению устройства. См. источник и лицензию данных.

Кнопки карт и маршрутов открывают внешние сайты с координатами выбранной станции или текстом поиска. Веб-поиск, сайты зарядных станций, сайты проекта и DIAGNOST AI открываются во вкладке или окне установленного браузера. Эти сайты получают обычные веб-запросы и могут применять собственные cookies, учётные записи и правила обработки данных. Некоторые из связанных сервисов являются проприетарными.

Перед первым открытием DIAGNOST AI приложение объясняет, что это внешний сервис, и локально сохраняет подтверждение пользователя. Ссылка автоматически не добавляет контакты, номер из поля набора или историю звонков. Данные, которые пользователь вводит на сайте, обрабатываются по правилам этого сайта.

Обновления и аналитика

Предварительная версия, распространяемая с сайта, содержит обновление по запросу пользователя. Проверка обновлений обращается к https://autonatoke.ru/evdial/; загрузка обновления получает APK с этого сайта. Веб-сервер получает обычные сведения о соединении, например IP-адрес. EVDial не реализует фоновую проверку обновлений или установку без участия пользователя.

В режиме сборки F-Droid обновление с сайта отключено, а разрешение на установку пакетов и файловый провайдер обновлений удалены. Команда обновления объясняет, что обновлениями управляет репозиторий, и может открыть установленный клиент F-Droid или сайт F-Droid. Выбранные репозиторий и клиент работают с сетью по собственным правилам.

В сборках Google Play обновление с сайта, разрешение на установку и файловый провайдер обновлений также отключены. После нажатия пользователем команда обновления открывает страницу EVDial в приложении или на сайте Google Play. Обновления распространяет Google Play по своим правилам.

В исходном коде приложения EVDial не реализованы сервисы аналитики разработчика, интеграция рекламных SDK или отправка отчётов о сбоях. Это утверждение не описывает телеметрию, которую независимо могут выполнять Android, мобильный оператор, SIP-провайдер, браузер или другое установленное приложение.

Манифест приложения не запрашивает доступ к местоположению или камере. Разрешения можно изменить в настройках Android; функции, которым нужен отозванный доступ, могут перестать работать. В манифесте отключено резервное копирование приложения средствами Android. Очистка хранилища EVDial или удаление приложения удаляет его закрытые настройки, историю SIP, сохранённые учётные данные и импортированный фон. Это не удаляет контакты, системный журнал вызовов, исходные записи разговоров или данные, уже переданные внешнему сервису.
